\chapter{Method}
To overcome the described issues, we try to control our bot using neural networks. 
To solve ambiguous situations like intersections, \textit{condition} our model on \textit{high-level commands} or \textit{intents} $c_t$. 
In the following, we describe how we collected the needed data, which network architectures we use, how we trained them, and how we improved the inference. 

\section{Data Collection}\label{sec:datacollection}
To collect data, we implemented a custom data collection node (\textcolor{red}{picture of UI}). 
We controlled the duckiebot via the keys 'w', 'a', 's', 'd' where 'w' = straight and 's' = backwards. 
Pressing 'a' and 'd' in addition to 'w' causes respectively the left or the right wheel to spin faster by a factor of $\omega_a$ or $\omega_d$ to handle left and right turns. (@Pankaj correct wording if this is wrong...)
These factors $\omega_a$ or $\omega_d$ and the overall velocity are hyperparameters that should be tuned using the data collection UI (figure...). 
The current intent is set using the keys 'i' = straight at intersections, 'j' = left at intersections, 'l' = right at intersections and 'k' = lane following when at no intersection. 
During collection, we save the current frame $f_t$, the current wheel velocities for each wheel $v_t = [v_t^l, v_t^r]^T$, the intent $c_t$ and the current pressed steering keys. 

\section{YOLO segmentation model}\label{sec:yolo}
Because we don't have street lights or pedestrains in the Duckietown, the street lanes are the only needed information for steering. 
Due to the described problems with the lane detection LX, we train a small YOLO model to segment the lanes in the given frame. 
We also crop the image, such that only the bottom is visible. (see fig \ref{fig:sem_example}:)

\section{Conditional Imitation Learning}
We tried multible ways to condition a neural network on high-level commands. in the following we describe the two most promising approaches. 

\subsection{Multible head architecture (MH)}\label{sec:MH}
\textbf{Architecture.} As vizualized in fig. \ref{fig:multibleHeads}, we first pass the current frame $f_t$ to a CNN backbone to produce visual features. 
Based on the current intent, we then pass these features to a specialized head, which then predicts the target wheel velocities $MH_{\theta}(s_t, c_t) \approx v_t$. \\
\textbf{Training.} We train the CNN and the four heads end-to-end using a 80/20 train/test split and minimize a simple MSE-loss $\mathcal{L}(\theta) = \frac{1}{\vert \mathcal{B} \vert}\sum_{(s_t, c_t, v_t) \in \mathcal{B}} (MH_{\theta}(s_t, c_t) - v_t)^2$, where $\mathcal{B}$ is a batch with batchsize $\vert \mathcal{B}\vert = 64$. 
We use Adam as an optimizer. 
Since the intents are not equally distributed in the dataset ('lane following' $\approx 73 \%$, 'left' $\approx 11 \%$, 'straight' $\approx 10 \%$, 'right' $\approx 6 \%$), we oversample the 'left', 'right', and 'straight' intents to get 40 \% of lane following and 20 \% of the other intents during training. 
We observed that this detail is crucial to get a successful model. In the end, we use the model with the lowest validation loss.

\subsection{Other approaches}
In this section, we'd like to briefly describe some other architectures that we tried but that either failed or did not produce the desired results. \\
\textbf{Naive approach.} First we tried to pass the current RGB frame $f_t$ directly a neural network (CNN with fully-connected layers afterwards). 
The intent was fed into the linear layer as a one-hot encoded four dimensional vector. 
We observed, that the model drove forward, but was barely able to react on changes to the lane. This approach likely failed, because the model used the whole image as an input and therefore recieved too much uneccecary information. 
We also assume, that the conditioning method was too weak to have an influence. \\
\textbf{Classification.} Because we used discrete control signals (describe that in data collection..) during data collection, we also tried if the model can accurately classify when to do which action.
The model therefore had 3 output neurons, referring to the three actions: 'w' = straight, 'w' + 'a' = left turn, 'w' + 'd' right turn. 
We tried this in combination with the multible head architecture from section \ref{sec:MH}. 
We observed, that the model is able to control the Duckiebot, but also shows a highly non-smooth and zigzagy driving style. 
We therefore decided not to pursue this approach any further.
