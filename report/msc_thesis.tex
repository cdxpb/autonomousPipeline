\chapter{Introduction}

\textcolor{red}{The following is my summary—we should go over this together.} \\
Duckietown is an educational and research platform that enables the exploration of autonomous driving concepts using a simple and low-cost environment. 
It also provides Learning Experiences (LX) in which we learned about basic concepts of self-driving cars. 
However, a number of problems arose during the LX that made it difficult or even impossible to control the Duckiebot reliably: \\
Most importantly, our Duckiebot shows \textbf{strong drift}, likely due to hardware issues. 
Because the provided odometry algorithms rely on correct wheel information, we were not able to control our Duckiebot with a PID controller. \\
Also, in the Computer Vision LX, we were supposed to do find lower- and upper-bounds of HSV values by hand to correctly segment lanes in pictures that are taken by the camera of the bot. 
However, we were not able to find good values, that are \textbf{robust under every lighting condtion}. 
As a consequence, the lane following module was not relyable. \\
We tried to adress these challenges via \textbf{conditional imitation learning} and making use of a small \textbf{segmentation model}. 
We find that this pipeline enables relyable control of our bot. 

\chapter{Method}
To overcome the described issues, we try to control our bot using neural networks. 
We solve ambiguous situations like intersections by \textit{conditioning} our model on \textit{high-level commands} or \textit{intents} $c_t$. 
In the following, we describe how we collected the needed data, which network architectures we use, how we trained them, and how we improved the inference. 

\section{Data Collection}\label{sec:datacollection}
To collect data, we implemented a custom data collection node (\textcolor{red}{picture of UI}). 
We controlled the duckiebot via the keys 'w', 'a', 's', 'd' where 'w' = straight and 's' = backwards. 
Pressing 'a' and 'd' in addition to 'w' causes respectively the left or the right wheel to spin faster by a factor of $\omega_a$ or $\omega_d$ to handle left and right turns. (\textcolor{red}{@Pankaj: correct the wording if this is wrong...})
These factors $\omega_a$ or $\omega_d$ and the overall velocity are hyperparameters that should be tuned using the data collection UI (figure...). In practise, we don't use backwards motion. 
The current intent is set using the keys 'i' = straight at intersections, 'j' = left at intersections, 'l' = right at intersections and 'k' = lane following when at no intersection. 
During collection, we save the current frame $f_t$, the current wheel velocities for each wheel $v_t = [v_t^l, v_t^r]^T$, the intent $c_t$ and the current pressed steering keys ('w', 'a', 's', 'd'). 
In total, we collected 10809 datapoints in about 20 min of continous driving.

\section{Conditional Imitation Learning}
We tried multible ways to condition a neural network on high-level commands. In the following, we describe the two most successful approaches. 

\subsection{Multible head architecture (MH)}\label{sec:MH}
\textbf{Architecture.} As vizualized in fig. \ref{fig:multibleHeads}, we first pass the current frame $f_t$ to a CNN backbone to produce visual features. 
Based on the current intent, we then pass these features to a specialized head, which then predicts the target wheel velocities $MH_{\theta}(s_t, c_t) \approx v_t$. \\
\textbf{Training.} We train the CNN and the four heads end-to-end using a 80/20 train/test split and minimize a simple MSE-loss $\mathcal{L}(\theta) = \frac{1}{\vert \mathcal{B} \vert}\sum_{(s_t, c_t, v_t) \in \mathcal{B}} (MH_{\theta}(s_t, c_t) - v_t)^2$, where $\mathcal{B}$ is a batch with batchsize $\vert \mathcal{B}\vert = 64$. 
We use Adam as an optimizer. 
Since the intents are not equally distributed in the dataset ('lane following' $\approx 73 \%$, 'left' $\approx 11 \%$, 'straight' $\approx 10 \%$, 'right' $\approx 6 \%$), we oversample the 'left', 'right', and 'straight' intents to get 40 \% of lane following and 20 \% of the other intents during training. 
We observed that this detail is crucial to get a successful model. In the end, we use the model with the lowest validation loss.

\subsection{Other approaches}
In this section, we'd like to briefly describe some other architectures that we tried but that either failed or did not produce the desired results. \\
\textbf{Naive approach.} First we tried to pass the current RGB frame $f_t$ directly a neural network (CNN with fully-connected layers afterwards). 
The intent was fed into the linear layer as a one-hot encoded four dimensional vector. 
We observed, that the model drove forward, but was barely able to react on changes to the lane. This approach likely failed, because the model used the whole image as an input and therefore recieved too much uneccecary information. 
We also assume, that the conditioning method was too weak to have an influence. \\
\textbf{Classification.} Because we used discrete control signals (as described in section \ref{sec:datacollection}) during data collection, we also tried if the model can accurately classify when to do which action.
The model therefore had 3 output neurons, referring to the three actions: 'w' = straight, 'w' + 'a' = left turn, 'w' + 'd' right turn. 
We tried this in combination with the multible head architecture from section \ref{sec:MH}. 
We observed, that the model is able to control the Duckiebot, but also shows a highly non-smooth and zigzagy driving style. (\textcolor{red}{link to a video?})
We therefore decided not to pursue this approach any further.

\chapter{Conclusion and Future Work}
\label{sec:conclusion}

To conclude... \\

Future work: With our learning based approach, we provide robust models, that can control the Duckiebot relyable. 
However, we did not incorperate street lights and pedestrains yet. Also, a fully autonomous car should also be able to navigate through the Duckietown by itself.
To achieve this, a high-level planner like A* or the continous version Anytime A* \textcolor{red}{(refence!!)} is needed to get the high level commands. 
Another way to get these is \textcolor{red}{the VLM approach of @Pankaj...} We leave these challenges as future work.
